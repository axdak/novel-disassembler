# v5 Patch Notes：故事结构 JSON 硬 Schema 保证

## 背景

用户要求最终故事结构 JSON 必须严格符合固定结构：

- 顶层只能有：介绍、角色集、事件集、地点集、线索集、阵营集、物品集。
- 各元素只能有标准字段和公共字段。
- 非标准字段必须放入详情。
- 详情字段有严格键名和值类型要求。
- 所有引用必须指向已存在元素。

## 本次修改

### 1. 新增 `scripts/story_schema_rules.py`

集中定义硬 Schema：

- 顶层字段集合。
- 各元素合法字段集合。
- 默认空结构。
- 字段类型和值域规则。
- 详情字段规则。
- 正式名称引用规则。
- 父级循环检测。
- 数量要求。

### 2. 强化 `validate_structure.py`

现在 `validate_structure.py` 会先运行硬 Schema 校验：

- 缺字段：error。
- 多字段：error。
- 规范外字段：error。
- 字段类型错误：error。
- 详情键名包含标点/空格/下划线：error。
- 详情数组项不是 `类型:名称`：error。
- 引用不存在：error。
- 父级指向自身/循环：error。
- 数量不足：标准模式 warning，`--strict` 模式 error。

最终交付必须运行：

```bash
python scripts/validate_structure.py --strict <项目目录>/故事结构.json
```

### 3. 强化 `validate_delta.py`

Delta 入库前现在更严格：

- `详情` 键名不合规直接 error。
- `详情` 数组项必须是 `类型:名称`。
- 交叉引用要求使用正式名称，不再把别名当作合格引用目标。
- 新增元素仍必须具备完整标准字段。

### 4. 重写 `references/story_structure_spec.md`

把故事结构规范改成硬约束文档，明确：

- 这是拆书，不是凭空创作。
- 示例只用于说明格式，不能进入实际结果。
- 所有元素必须来自原文或有证据的治理结果。
- 数量要求在拆书场景下不得压过原文事实。

### 5. 更新 `SKILL.md`

最终结构整理阶段增加硬卡口说明：

- `故事结构.json` 必须通过 `validate_structure.py --strict`。
- `--strict` 会把数量不足、介绍/分组/标签缺失等最终质量项升级为错误。

## 保证边界

脚本可以保证：

- JSON 格式合法。
- Schema 精确。
- 字段类型和值域正确。
- 交叉引用存在。
- 详情字段规范。
- 无规范外字段。

脚本不能独立保证：

- 某个角色是否真的重要。
- 某个事件粒度是否最佳。
- 某条伏笔是否文学上成立。
- 人物关系是否解读得足够深。

这些文学质量仍需要结合原文上下文包、章节分析、周期审计和人工/模型审计共同完成。
